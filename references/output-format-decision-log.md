# 输出格式决策日志

## CSV 文本格式列保护

### 尝试1：`="value"` 公式写法（已放弃）
- **实现**：`lambda v: f'="{v}"'`
- **结果**：Excel 单元格显示 `="123..."` 公式文本，不是纯数字
- **用户反馈**：「明显和要求不符，我要的结果就是纯长字符串」
- **放弃原因**：用户明确反对

### 尝试2：前导单引号 `'value`（当前方案）
- **实现**：`lambda v: f"'{v}"`
- **结果**：CSV 中写为 `,'123...,`，Excel 把 `'` 识别为文本前缀，显示时不可见
- **工作方式**：Excel 的 CSV 导入器遇到前导 `'` 会将其从单元格内容中移除，`'` 是 Excel 文本前缀标记

### 备选方案评估
- **强制 `text/plain` CSV 格式**：不可行，CSV 是纯文本格式无样式控制
- **Excel 导入向导提示用户选 UTF-8**：无法自动化，违背"双击打开就能用"的需求
- **改为 .xlsx 作为主要输出**：可行但需保留 CSV（用户需求）

## XLSX 值类型转换

### 问题症状
- 设了 `number_format = '@'` 但 Excel 仍左对齐
- 设了 `number_format = 'YYYY-MM-DD HH:MM:SS'` 但筛选不是树状结构
- 设了 `number_format = '#,##0.00'` 但无法参与计算

### 根因分析
`number_format` 只改变**显示方式**，不改变**底层数据类型**。
- 字符串 `"799.00"` + `#,##0.00` 格式 → 显示为 799.00 但仍是文本
- datetime 对象 `datetime(2025,10,19,14,25,59)` + `YYYY-MM-DD HH:MM:SS` 格式 → 正常日期

### 正确做法
1. 扫描时识别列的类型（文本/日期/数值）
2. 写入前按类型转换值：
   - 日期列：`datetime.datetime.strptime(s, fmt)` → datetime 对象
   - 数值列：`float(val)` → float
   - 文本列：保持字符串
3. 再设 `number_format`

### 易错点
- `float("799.00")` 返回 `799.0`，不是 `799` → 不影响 `#,##0.00` 显示
- `float("-")` 抛出 ValueError → 需先过滤纯短横
- 短横替换为 `"0"` 后，`float("0")` 返回 `0.0`

## 数字保护阈值

### 验证过程
- 初始：15位（Excel有效数字精度）
- 实测：12位的 `955956980424`（商品ID）在Excel中已可能触发科学计数法
- 修正：12位（含），覆盖商品ID/订单号/流水号等常见场景

### 数字保护策略对比
| 阈值 | 覆盖范围 | 误判风险 |
|------|---------|---------|
| 15+ | 超级长数字（19位订单号） | 低 |
| 12+ | 商品ID + 订单号 | 中等（短数字ID被当文本） |
| 10+ | 手机号 + 订单号 | 高（10字段数字也可能是有意义的数值） |

当前使用 12+ 位阈值，后续可根据反馈微调。

## 短横替换

### 背景
电商CSV金额列中常见纯 `-`/`–`/`—` 表示"此记录无金额"。
- 不是 null / NaN
- 不是数据缺失
- 实为值 = 0

### 决策
替换为 `"0"`（字符串），写入 XLSX 时转 `float(0.0)`。
不替换为 `null` 或空字符串，避免公式报错。
不替换为 `None`，openpyxl 写入 None 会变成空单元格。
