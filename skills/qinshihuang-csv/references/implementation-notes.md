# qinshihuang-csv21 实现笔记

## 架构决策

### 使用 pandas `header=None` + 自定义表头检测
- **原因**：电商CSV表头不在第1行（可能有前置空行/备注行/平台声明行）
- **方案**：`pd.read_csv(header=None)` 读所有行，`auto_detect_header()` 扫描前5行找真实表头
- **坑**：千万不能用 pandas 的 `header=0` 自动检测，它会把备注行当数据读进来

### `on_bad_lines='skip'` 处理行格式混乱
- **原因**：淘宝CSV的地址字段含未转义逗号，导致行内字段数 > 表头列数
- **方案**：`on_bad_lines='skip'` + `header=None` 组合使用
- **坑**：`on_bad_lines` 是 pandas ≥1.3 才有的参数

### `dtype=str` + `keep_default_na=False`
- **原因**：长数字（订单号）防止被 pandas 自动转为 float 导致精度丢失
- **原因**：空单元格防止被转为 NaN（NaN 会干扰后续清洗）

### 四层编码检测管线
- **Layer 1 (BOM)**：快速识别 UTF-8-SIG / UTF-16 LE/BE / UTF-32
- **Layer 2 (charset-normalizer)**：主方案，统计检测+置信度校验
- **Layer 3 (chardet)**：兜底，对 `language='zh'` 降门槛到 0.2
- **Layer 4 (fallback)**：40+编码广度尝试 + CJK容错验证
- **为什么不用 CleverCSV 做编码检测**：只是 chardet 的封装，不增加检测能力

### 坏字节容错策略
- 文件可能有 1-2 个损坏字节（如 position 409 的 0xb5）
- 严格模式先试 → 失败后用 `encoding_errors='replace'`
- CJK 编码在 fallback 中用 `errors='replace'` + CJK字符数验证

## 字段清洗策略

### 循环 strip 的由来
特殊字符组合如 `  ,,￥123456789012345,,￥，  `：
- 1次 strip → `,,￥123456789012345,,￥，`（首尾空格没了）
- 2次 strip → `￥123456789012345,,￥`（首尾逗号没了）
- 3次 strip → `123456789012345`（首尾币种符号没了）
→ 必须 loop 直到稳定

### 列格式优先级
文本格式 > 日期格式 > 数值格式，互斥。
原因：同一列的订单号可被同时判定为"12+位数字"（文本）和"可解析为数字"（数值）。
解决方案：文本/日期列排除出数值候选集。

### 短横替换策略
- 纯 `-`/`–`/`—` 替换为 `"0"`
- 只在数值列和非文本日期列中替换
- 备注列也有大量短横但不替换（不是数值上下文）

- 字段类型：19位纯数字订单号、日期时间、金额、百分比、短横占位、备注
